# 项目代码审查修复记录（2026-10-15）

本次修复对应 [代码审查](project_code_review_20261015.md) 的六项问题。原有实验数据及 A2G v1 冻结清单没有覆盖或改写；本次运行使用独立配置和输出目录。

1. RGB-D 安全守卫现在单独检查正前方深度覆盖。只有边缘像素有效时返回 `SENSOR_STALE`，有限的远处深度仍可判为空闲。
2. 36 组批量脚本只接受本次启动后新建的运行目录、匹配的运行时间和 `experiment_id`。失败重跑无法借用旧 `PASS`；本次生成的有效报告仍可在清理阶段退出码非零时保留。
3. 消息路线按配置的水平停靠半径截断，并把消息目标坐标交给 RGB-D 控制器的停靠判断。若道路无法进入停靠半径，路线保持可达终点，由现有局部安全控制约束。
4. 当前 `require_cross_device_consensus: false` 保留 UAV 或 UGV 单设备候选触发初次路线的规则。显式设为 `true` 时，目标记忆提交必须有 TTL 内另一设备的有效近邻候选；不兼容的单设备策略配置会被拒绝。目标切换另有原有的迟滞门槛。
5. S1 发送与本地复核都采用实际加载的检测模型来源，不再要求权重文件名固定为 `yolo26x`。
6. 新增 `shared_spatial_v2` 场实现与配置。给定种子和 UAV/UGV 天线坐标，同一位置的随机场取值与访问顺序无关；在线与离线使用相同实现。它采用 1024 个随机傅里叶特征，指数协方差为有限特征近似。A2G v1 默认仍选原有的精确单轨迹采样方式；跨策略轨迹对照应显式包含 [a2g_spatial_shared_v2.yaml](../../configs/communication/a2g_spatial_shared_v2.yaml)。
