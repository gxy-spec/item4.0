## 数据和脚本清理

清理前识别到 111 个 `FAIL`/`ERROR` 回合。按照验证报告状态和显式废弃批次白名单，共删除 84 个目录、14,686,020,850 bytes（约 13.68 GiB）：

- 删除所有已被后续 PASS 回合替代的 FAIL/ERROR 运行目录；
- 删除调试批次 `e7_revised`，其正式替代为 `e7_revised_v2`；
- 删除未完成的首版 `multiscene_abc_formal_20261010`，其正式替代为 36/36 完成的 v2；
- 删除旧消息过期恢复启动脚本及两个已被 `persistent_target_memory` 取代的临时 smoke 配置；
- 删除 Python、pytest 等可再生成缓存；
- 删除旧硬编码清理脚本，改用具有 dry-run、路径边界和 JSON 清单的通用审计清理工具。

完整、机器可读的删除记录位于 `docs/experiments/output_cleanup_manifest_20261012.json`。上述数据已从本地磁盘直接删除，不能依靠 Git 恢复；清单只保留路径、大小、状态和原验证报告哈希，不保留传感器文件。

清理后数据根目录约 64.40 GiB，共保留 205 个 `PASS` 验证回合；另保留一份没有采用统一 `validation_report.json`、但被正式报告引用的 E2 候选基线。当前数据根目录中不再存在带 `FAIL` 或 `ERROR` 状态的验证报告。

## 当前已知边界

- `run_stage1_dynamic.py` 集成内容较多，后续新增物理信道前宜把信道、消息队列和任务状态机逐步拆为独立模块，但当前测试未发现功能性阻断。
- v2 的 36 组历史配置包含现已禁用的 `hold_after_grace` 策略，仅用于结果溯源。目录内已增加明确警告，不应由当前 runner 直接重跑。
- 项目配置仍包含本机 Windows 绝对路径；这符合当前单机 CARLA-Air 部署，但跨机器复现时应通过环境变量或机器配置层覆盖。
- YOLO 权重约 118 MiB，按 `.gitignore` 保留在本地，不上传 GitHub。
- 最终论文级基线需等待目标识别和物理信道模型冻结，再用相同场景、相同种子和相同感知版本重跑配对实验。
